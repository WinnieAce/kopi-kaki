# Kopi Kaki Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Kopi Kaki, a free, installable, offline web app with a Kopitiam room (an order builder that teaches kopitiam ordering terms and makes the exact order at home) and a Café room (café coffee, tea and matcha recipes), for a general audience including children.

**Architecture:** A static single-page app. Content (ingredients, drinks, terms) is JSON validated at build time; pure functions in `src/core` resolve an order from choices into a name, recipe, cup, caffeine and allergens; user data is saved on the device behind one storage interface. Modules are ported one by one from First Pour, the owner's cocktail app, through tests; nothing alcohol-related is carried over.

**Tech Stack:** TypeScript, React, Vite, React Router, Zod, idb-keyval, Motion, vite-plugin-pwa, @vite-pwa/assets-generator, Vitest, Testing Library, fake-indexeddb, axe-core, oxlint, subset-font, Fontsource (Figtree, Young Serif, Noto Serif, Noto Serif SC). Hosting: Cloudflare, building from GitHub.

**Spec:** `docs/superpowers/specs/2026-10-21-kopi-kaki-design.md`

## Global Constraints

- App name `Kopi Kaki` in `src/config.ts` as `APP_NAME`; `FEEDBACK_URL = ''` (feedback link hidden while empty).
- No server, accounts, cookies, personal data, analytics, or runtime requests to other hosts. Nothing entered leaves the device.
- No alcohol: no `abv` field; content and source scans as in Task 7.
- Units `ml`, `g`, `tsp`, `tbsp`, `piece`; servings 1 to 8.
- Caffeine levels: None 0 · Low under 40 · Medium 40–99 · High 100 and over (unrounded mg). Display: "No caffeine", else "about N mg", N to the nearest 5 below 20 mg (never below 5) and nearest 10 from 20 mg.
- Allergens, in this order: `dairy`, `soy`, `gluten`, `nuts`.
- Choice groups in name order: `milk`, `strength`, `sugar`, `temp`. Factors: sweet (kosong 0, siew-dai 0.5, normal 1, ga-dai 1.5); strong (po 0.75, normal 1, gau 1.4, di-lo 1); dilute (po 1.3, normal 1, gau 1, di-lo 0).
- Chinese characters on kopitiam drink names and the room header only, marked `lang="zh-Hans"`. Never on ordering terms.
- Tap targets at least 44 × 44 CSS px; WCAG 2.1 AA in every palette, light and dark; checked at 360 and 375 px wide.
- Fonts self-hosted: Figtree (body), Young Serif (café display), Noto Serif 700 and Noto Serif SC 900 (kopitiam display). Latin subsets only for Latin faces.
- Motion as spec 7.5. Easing tokens `--ease-out: cubic-bezier(.23,1,.32,1)`, `--ease-in-out: cubic-bezier(.77,0,.175,1)`. Only transform and opacity animate (plus cup fill colour). The Motion library is used only for the tab highlight and making-mode swipes. Loops rest after 5 seconds. Every animation honours reduced motion.
- Drawn icons only; no emoji or symbol characters as icons.
- `src/core` imports nothing from `src/storage`, `src/screens` or `src/components`.
- Tests run in jsdom, which has no `startViewTransition` and no `matchMedia`; code checks for both.
- Every screen task (11, 14–19) includes a test `has no axe violations` calling `expectAccessible` (Task 11) on the rendered screen.
- No local machine directory paths in any markdown file. First Pour is referred to by name; whoever executes this plan supplies the location of its checkout. A code graph of First Pour's `src` is in `graphify-out/` (git-ignored) for "what uses X" questions.
- Use the latest stable version of each dependency at install time. Node 22 or newer.
- Commit locally at the end of every task; never push unless the owner says so. `npm test`, `npm run lint` and `npm run build` pass before every commit (from Task 2 on, `build` includes content validation).

## Review Focus

1. **Order-style searches** such as `kopi o kosong`, `Milo Peng`, `咖啡`, `  BARLEY ` find the drink a person means: every word must match the drink's name, Chinese name, ingredients or option words. (Task 6)
2. **Hand-edited or stale addresses** (`?milk=c&milk=o&sugar=Kosong&fizz=1`, a group the drink lacks, a blocked pair) resolve to a sensible order and never an error: first value wins, values are case-sensitive, unknown keys and values are ignored. (Tasks 3, 15)
3. **Saved data and backups made before a content change** (an option a drink no longer offers, a removed drink, a pair that is now blocked, the same order saved twice) are tidied silently on load and on import. (Task 8)
4. **Storage failing after the app has loaded** (a save rejects): the app keeps working in memory and shows the not-saved notice. (Task 11)
5. **Extreme measures from scaling** (8 servings of 400 ml; ¼ tsp at Siew Dai) read cleanly and never show zero. (Task 4)

### Task 3: Core — resolving an order

**Files:**
- Create: `src/core/order.ts`
- Test: `src/core/order.test.ts`

**Interfaces:**
- Consumes: Task 2 types, `OPTIONS`, `FACTORS`, `findOption`, `CHOICE_GROUPS`.
- Produces:
  - `type Choices = Partial<Record<ChoiceGroup, string>>`
  - `type ResolvedLine = { ingredientId: string; amount: number; optional: boolean; note?: string }`
  - `type ResolvedStep = { text: string; technique?: Technique; ingredientIds: string[]; caution?: Caution }`
  - `type ResolvedOrder = { drink: Drink; choices: Choices; name: string; meaning: string; lines: ResolvedLine[]; steps: ResolvedStep[]; cup: CupId; colour: string; notes: string[] }` — `choices` holds a value for every group the drink allows.
  - `resolveOrder(drink: Drink, requested?: Record<string, string | undefined>): ResolvedOrder`
  - `isBlocked(drink: Drink, choices: Choices, group: ChoiceGroup, option: string): string | null` — the reason, or null
  - `normaliseChoices(order: ResolvedOrder): Choices` — only non-default choices
  - `choicesToSearch(order: ResolvedOrder): string` — e.g. `milk=c&temp=peng`, groups in `CHOICE_GROUPS` order, defaults omitted
  - `choicesFromSearch(params: URLSearchParams): Record<string, string>` — first value of each key
